# Policy Auditability

Source inspiration: https://skillissue.dev/patterns/

- Record the source and version/date supporting each material claim or rule.
- Separate source text from interpretation and implementation choices.
- If a source, license, or approval is missing, state that it is unresolved; do not guess.
- For a rule change, record the reason, scope, expected effect, and compatibility impact.
- Include valid, invalid, boundary, and missing-information tests where relevant.
- Preserve the prior evidence when correcting an entry and explain the correction.
- Fix underlying inconsistencies rather than bypassing validation.
- Report modified files, checks, results, and unresolved questions.
